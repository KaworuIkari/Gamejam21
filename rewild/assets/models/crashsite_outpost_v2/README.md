# 坠机之地 V2 · 连续机壳修正版

本版按确认需求保留原有大侧面破口、顶部破洞、灰白红配色和初驻据点布局，修复正常装甲区的非设计镂空。旧版保留在原目录，本版为独立文件包。

## 修复内容

- 将六段分离机壳、驾驶舱外壳和尾段改为一个共享顶点的连续网格 `Fuselage_Continuous`。机头封闭，尾部保留撕裂，断口连接内外层，壳厚约 0.10 米。
- 装甲块以材质色差、表面条带和磨损细节区分，不再通过真实空隙分割。
- 重建连续引擎主壳，壁厚约 0.16 米，保留进气口、排气口和破损后缘。
- 将尾部零碎缺口整理为连贯断口，避免边角异常连接。
- 检查连接主翼、脱落翼片和尾翼的实体边界。翼片表面红色条带等装饰不计入实体闭合检查。
- 机舱地板、工作区、储物区、坡板及周边主体布局沿用。部分随机磨损和散布细节有所变化。

## 打开与使用

打开 `crashsite_outpost_v2.blend`，贴图已打包，默认材质预览。Z → 材质预览可手动切换；小键盘 0 查看相机；F12 渲染。

`previews/assembly.png` 为总览，`front_detail.png` 为机头侧面，`interior.png` 为舱内，`intact_side.png` 用于查看背面完整机壳。

本版共 32 个模块、105 个装配实例。`assets/*.glb` 是独立模型，`assets/*.tscn` 包含主要结构的静态碰撞。`Fuselage_Continuous.glb` 单独提供完整主壳；表面条带和磨损放在 `Hull_Surface_Details.glb`，两者保持相同原点装配。

Godot 4.x 可导入 `project.godot`。示例为兼容性渲染器：左键旋转、滚轮缩放、1/2/3 切换视角、Tab 切换步行、WASD 移动、空格跳跃、Esc 释放鼠标。迁移到旧工程时应替换旧机壳组合，而非在其上叠加新机壳。包装场景的路径为 `res://assets/`，改变目录时同步修改引用。

模型单位为米，机身约 24 米长。机头、机身、尾部现在是一个整体；如需重新分段，应在编辑器中保持相同切分边界，不要重新缩短各段留下空隙。展示副本和隐藏的原始模块可能共享网格。

## 验证结果

- `shell_validation.json`：连续机身和引擎主壳均为 0 未封口边、0 非流形边；机身 582、引擎 160 个表面/接缝射线采样全部命中。三个翼片实体也通过边界检查。
- `exported_shell_validation.json`：对导出的机身 GLB 按几何位置合并材质/UV 拆分顶点后复检，482 个几何顶点、968 个三角形，0 未封口边、0 非流形边。位置量化精度为 0.00001 米。
- `validation.json`：32 个 GLB 的二进制结构、索引和场景引用检查通过。
- `route_validation.json`：坡板、入口和主通路的 27 个净空射线与 31 个地板采样通过。

闭合检查针对机壳材料本身的内外层及断口封边，不表示把设计破口堵住。装饰条带可为开放面，其下有连续机壳。以上检查和四角度 Blender 渲染不替代 Godot 角色物理、性能或动态破坏验证；尚未在 Godot 实机运行。

`build_assets.py`、`repaired_hull.py` 和 `kit_common.py` 为可重建源代码；生成时仍需要原始自然素材目录。`prepare.py` 是从上一版脚本迁移的开发辅助，普通使用与直接运行本版 `build_assets.py` 不需要它。原素材树木、石块与贴图沿用原授权条件。
